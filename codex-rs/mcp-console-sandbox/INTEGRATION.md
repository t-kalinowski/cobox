# Current integration inventory

This inventories the extraction from `rust-v0.160.1`, commit `d27764b82f7118f674371e6d6e76271d9d606edb`, carried forward from `mcp-console/sandbox-runner/rust-v0.154.0` at `56d877c8e235af07adba2751d3d077ec27d030b2`. Only the pinned release is supported. Use this inventory with the source and [reapplication procedure](REBASE.md) when upgrading.

## What the patch carries

Upstream already supplies filesystem/network policy, the managed proxy, Seatbelt, seccomp, bubblewrap, and namespace-init cleanup. The patch adds a [standalone configuration boundary](PROTOCOL.md), target-environment isolation, optional trusted Seatbelt extensions, and one [supervised lifetime](LIFECYCLE.md) with cancellation, caller-death observation, private storage, and cleanup-error reporting. Native Linux waiting helpers also release target stdin promptly. These additions do not imply that every other upstream execution path lacks process management or cleanup.

The shared policy models, Seatbelt policy files, seccomp rules, proxy implementation, vendored bubblewrap, and helper build recipe remain unchanged. No Console-specific policy defaults, sideband framing, application restart, or watchdog are included. Behavioral contracts and their tests are maintained in [PROTOCOL.md](PROTOCOL.md) and [LIFECYCLE.md](LIFECYCLE.md#executable-acceptance-tests); historical handoffs do not override them.

## Runner modules and native assumptions

### Windows integration

Windows support selects Console's identity once at executable startup. Existing Codex callers default to their original identity and retain their descendant-preservation behavior. Resource naming and Job retirement live in small modules in the existing Windows backend; the runner owns transport validation, built-in profile selection, owner monitoring, and private storage. The loopback correction below repairs enforcement of an existing native network policy. See the [Windows validation limits](WINDOWS.md#validation-limits), including the unresolved unelevated deletion boundary.

All paths below are relative to `codex-rs/windows-sandbox-rs/`.

`src/unified_exec/tests.rs` also corrects native PowerShell fixture lifetimes: ConPTY input stays open during lifecycle checks, and an independent root-exit observer releases the captured descendant without waiting for its inherited output handles to close. The test locator supports PowerShell on PATH. Native runtime behavior is unchanged by these fixture corrections.

`src/wfp/loopback.rs` supplements the native firewall rules with persistent account-scoped ALE filters for offline TCP/UDP loopback. Proxy-port exceptions and `allow_local_binding` retain their existing meanings. Setup version 6 requires an approved refresh and fails if filter installation fails. Reconfiguration and uninstall remove the product's previous filters transactionally. This is a shared native-backend correctness fix, isolated in a new module; it changes no permission profile or core source. Review the stable filter-key namespace, port complements, setup migration, and removal together when rebasing.

## Procfs, control, and lifetime review

[LINUX_COMPATIBILITY.md](LINUX_COMPATIBILITY.md) owns the fresh/inherited procfs comparison, runtime prerequisites, and downstream differential evidence. The runner's injected identity test checks acceptance only. Procfs remains necessary for outer descriptor hygiene, storage permission changes, native setup, and verified descriptor execution; removing host process discovery did not make execution procfs-free.

Readiness obtains namespace init's host identity from kernel credentials. Preserve the optional pidfd path and native-channel retirement, including explicit failure when native wait status is missing or the deadline expires. The [lifecycle contract](LIFECYCLE.md#boundaries-and-intentional-differences) defines these outcomes. Init uses descriptor `read` / `write` permitted by the unchanged restricted-network filter; the host configures credentials before launch. The control endpoint never becomes a policy-update interface or inherited target descriptor. That descriptor boundary is not a claim that an unrestricted workload cannot reach supervisor authority indirectly. External execution without a proxy has no native setup handshake; existing supervision forwards signals and retires the original group on Linux, with outer enforcement responsible for escaped descendants.

Review Linux's direct-child creating thread, namespace-init re-arming after credential/exec transitions, native TERM links in [proxy_lifecycle.rs](../linux-sandbox/src/proxy_lifecycle.rs), synthetic-mount supervision, and [vendored bubblewrap](../vendor/bubblewrap/bubblewrap.c). Preserve the [runner-loss startup windows](LIFECYCLE.md#owned-stdio-process-groups-and-linux-parent-death) even when death-chain tests pass.

The independent observers in [ownership_tests.rs](tests/lifecycle/ownership_tests.rs) use pidfds, host child lists, and `NSpid` to verify exits and clean failed fixtures. These are test-host requirements, not runner prerequisites. Review fault-interposer checkpoints against actual syscall/helper boundaries without substituting sleeps or retries. [README.md](README.md#build-and-validation) owns packaging instructions; [REBASE.md](REBASE.md) owns upgrade validation and revision-specific evidence.
