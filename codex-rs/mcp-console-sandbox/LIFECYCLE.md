# Standalone lifecycle contract

The default execution path owns one sandbox lifetime. Its single application supervisor owns native launch, descendant retirement, optional private storage, and the optional upstream network proxy. Linux's native namespace init and bubblewrap helpers provide native setup and namespace lifetime control. macOS's short native stage applies Seatbelt and execs the target in the same process. This document covers Unix; [WINDOWS.md](WINDOWS.md#lifetime-and-storage) defines Windows Job and owner semantics.

The JSON shape and all defaults are defined in the [complete configuration reference](PROTOCOL.md#lifecycle-object). Managed unrestricted files retain the ordinary lifecycle below, with weaker guarantees against malicious interference. External execution without a proxy uses direct process supervision: Linux covers its original process group, while macOS retains descendant observation. An outer sandbox must retire descendants outside those mechanisms. Crashes or interference can leave processes or storage and can undermine other restrictions through shared writable host state.

## Configuration

Both [input modes](PROTOCOL.md) accept this optional object:

```json
{
  "lifecycle": {
    "parent_pid": 12345,
    "sigterm": "retire",
    "private_tmp": {
      "parent": "/absolute/parent",
      "environment": ["TMPDIR", "TMP", "TEMP"]
    },
    "cleanup_timeout_ms": 1000
  }
}
```

| Field                | Default and behavior                                                                                                                                                                                                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `parent_pid`         | Absent/null disables caller-death retirement. A supplied PID must be the live direct parent at capture. PID reuse cannot substitute another parent. Once captured, its death requests retirement and exit 0. An already-invalid parent is a launch error.                                                                        |
| `sigterm`            | `"forward"` forwards SIGTERM according to inherited signal state. `"retire"` makes SIGTERM request retirement and exit 0, including when SIGTERM was inherited ignored or blocked.                                                                                                                                               |
| `private_tmp`        | Absent/null creates no private directory. Otherwise the supervisor creates a mode-0700 container and writable `data` child. Each explicitly named environment variable receives the absolute data path. The optional absolute `parent` defaults to the supervisor's native temporary directory. An empty export list is allowed. |
| `cleanup_timeout_ms` | Absent/null uses 1000 ms. Values 1–60000 bound descendant retirement after completion or cancellation; this is not a target execution timeout or a filesystem deletion deadline.                                                                                                                                                 |

Unknown lifecycle fields and invalid names/values fail before target execution. Private storage adds a writable location without removing other caller-granted write access. Cleanup handles replacement data directories, mode-zero directories, and symlinks without following them outside the private container. No application policy defaults are inferred.

## Sequencing and observable behavior

Signals are captured before runtime startup. After request acceptance the supervisor validates the configured parent, captures terminal ownership, isolates an owned noninteractive runner, creates private storage, prepares the sandbox/proxy, spawns the native stage, and establishes platform lifetime tracking before releasing its private gate. External execution without a proxy starts the target directly and does not wait for a native setup handshake. Asynchronous preparation also observes cancellation. The supervisor checks cancellation again after native readiness and before each setup write. When startup is cancelled, it retains the channel through the retirement attempt, including for a reader stopped partway through setup. macOS closes the gate before target execution; Linux namespace init retains it as a close-on-exec control endpoint. No target code, including loader constructors, receives the descriptor. Target loader and private-directory environment variables are applied at this final boundary; helpers do not use the target's private TMPDIR for their own mount bookkeeping. A failed or timed-out retirement retains storage as described below.

The supervisor forwards HUP, INT, QUIT, and optionally TERM. Inherited ignored or blocked signals remain ignored or blocked in the target, including SIGCHLD and the platform's highest catchable signal. The supervisor maintains independently waitable children. The standalone pre-exec hook restores target dispositions and the complete original mask after the standard subprocess library's resets. On Linux the standalone namespace-init loop owns control-channel signals and direct HUP/INT/QUIT/TERM delivery through signalfd, with SIGCHLD blocked before spawning so child exit cannot be lost. Direct delivery targets the workload group once; only a missing group (`ESRCH`) causes a PID send. Runner control messages address the known target PID.

A completed native root's status takes precedence over pending cancellation. On normal/nonzero exit, interruption, or configured retirement, the supervisor retires descendants, restores terminal ownership, stops the proxy, and removes private storage. Only then does it return the target's exit code, `128 + signal`, or the configured retirement status. Discovery, termination, timeout, terminal restoration, proxy, and deletion errors produce a nonzero result and a stderr diagnostic. A discovery/termination failure remains an error even if a later pass finds no process; private storage is retained when retirement cannot be established.

An incomplete framed request is cancellable without transport EOF. Before acceptance, no lifecycle options are available and cancellation is a startup error. [PROTOCOL.md](PROTOCOL.md#framed-descriptor-configuration) defines direct stdio inheritance and prompt target-stdin closure.

macOS transfers an exclusively owned foreground terminal to the target group and restores it after retirement. If the caller group has a peer, that group retains ownership and the supervisor relays terminal signals. Linux retains the caller's foreground ownership. Bubblewrap and direct external launches create separate target sessions; inherited terminal descriptors remain usable, and terminal INT is relayed through namespace init or the original external process group.

## Owned stdio process groups and Linux parent death

A runner with a validated `lifecycle.parent_pid` enters its own process group when neither stdin nor stdout is a terminal. Stderr is deliberately excluded from this decision: piped stdin/stdout with inherited terminal stderr remains an owned stdio launch. Isolation happens before private storage, proxy preparation, or native launch. An existing group leader stays in its group. The runner retains its PID, direct parent, session, and original standard-stream open file descriptions; no fork, `setsid`, or stream relay is added.

Terminal ownership is captured before this change. A caller sharing the original group retains its foreground terminal. Signals addressed to that group now reach the caller, so a caller wishing to interrupt the workload must send the signal to the runner explicitly. Killing only the configured caller, or killing its process group, requests ordinary retirement in the surviving runner. Successful retirement still precedes private-directory deletion and exit. Launches without a configured parent, and launches with terminal stdin or stdout, retain the caller's group and terminal behavior. The native workload's existing separate group/session is unchanged.

On Linux the trusted direct native child arms `PR_SET_PDEATHSIG(SIGKILL)` before exec and rechecks the runner PID captured before spawning. Only syscalls and allocation-free errors run in that hook. The current-thread runtime spawns this child on the main thread, which remains alive through retirement; the kernel link follows the creating thread, not merely the process. The supervising runner requests a SIGCHLD wakeup on configured caller death, then verifies its direct-parent relationship before retiring the native lifetime.

The trusted helper unblocks the supervisor's captured forwarding-signal mask so native proxy bridges can receive their existing TERM parent-death signals. The final target still receives the caller's original dispositions and mask. Native synthetic-mount supervision and bubblewrap's `--die-with-parent` provide subsequent links. The namespace init re-arms SIGKILL in the existing leaf execution hook, after bubblewrap's credential/exec boundary and before readiness. Credential and exec transitions can clear death signals, so the direct-child link alone is insufficient.

For restricted filesystem policies, after native readiness, the parent-death chain links runner loss to termination of native helpers, proxy bridges, and detached workload descendants in the owned PID namespace. The target need not inherit a death signal: termination of namespace PID 1 terminates the namespace. No private-directory deletion is promised after the runner dies. These links and their creating-thread/exec rules must be reviewed when rebasing; see [INTEGRATION.md](INTEGRATION.md).

There is a remaining native startup limit. Bubblewrap clears or loses death signals at forks and privileged exec/credential transitions, then arms its own links later. Its namespace child can be waiting on `child_wait_fd` or doing mount setup before that arming or the leaf hook. The leaf cannot promise retirement of every native setup process if the runner dies in those internal windows, especially across a setuid system helper's exec. The execution gate still prevents an unreleased target from starting after the runner closes it. Tests cover death before/after the direct child's pre-exec arming and at native readiness, partial setup, and a stopped setup reader; they do not establish complete coverage of bubblewrap's earlier internal windows. Vendored bubblewrap retains its existing supervision. The native namespace init additionally accepts runner signals and retirement through the private control channel.

## Boundaries and intentional differences

Linux bubblewrap supervision waits for its known direct native child. The native monitor reaps namespace init after the kernel retires the namespace; this is the cleanup barrier. No host subreaper, `/proc/*/task/*/children` enumeration, or `NSpid` lookup is needed. Signals travel over the private native channel, and caller death wakes the supervisor through `PR_SET_PDEATHSIG(SIGCHLD)`. Linux waits on descriptor and signal events rather than a fixed polling interval.

Fresh and supported inherited procfs use the same backend and policy. Inherited procfs can expose host PIDs and readable metadata; this is not a grant of access to process environment, root, cwd, fd links, memory, or control interfaces. The [procfs review matrix](LINUX_COMPATIBILITY.md#procfs-review) covers those interfaces and the actual supervisor.

A pidfd attached by the kernel to the readiness message (`SO_PASSPIDFD`/`SCM_PIDFD`, available since Linux 6.5) permits termination of a stopped namespace init. This handle retains the sender's identity even if init exits and its numeric PID is reused before readiness is received. On older kernels or when host policy disables the socket option or pidfd signalling, ordinary retirement closes the native channel. The runner never opens a pidfd from the queued numeric PID. A stopped or kernel-uninterruptible init can then exceed the deadline. Missing wait status, termination errors, and deadlines produce a nonzero result with private storage retained; they never count as successful cleanup.

The native execution gate uses permitted descriptor read/write on its private socket; the kernel supplies the readiness sender's identity. Application sidebands must also obey the [upstream restricted-network rules](PROTOCOL.md#network-and-target-environment).

The supervisor observes root completion without reaping it and preserves that identity until retirement finishes. On Darwin it also enumerates and retires live members of the original owned process group, including children orphaned before fork-event discovery. A separate host process outside that group is not part of this retirement.

Darwin provides neither a Linux-style subreaper nor pidfd signalling. The supervisor observes fork/exit events and records PID plus start time, retaining observed descendants across `setsid`, reparenting, and root exit. A descendant that leaves the owned group and orphans before observation remains outside this guarantee. There is also a residual identity-check-to-kill PID reuse race on Darwin. These are platform boundaries, not recovery promises.

If the sole supervisor crashes or receives SIGKILL, there is no custom recovery. Linux workload termination after native readiness follows the chain above; directory deletion, continued proxy availability, and terminal restoration are not guaranteed. On macOS, surviving workloads remain subject to inherited native sandbox restrictions, but termination is not guaranteed. There is no recovery from a stopped or hung runner, nor a cleanup guarantee when a harness kills every descendant or all cleanup owners.

Trusted caller-supplied Seatbelt extensions can grant permissions and therefore can deliberately override native restrictions. The target receives no supervisor task port, host process-control descriptors, configuration transport, or proxy-control interface under the tested restricted policy. This does not protect the supervisor from an unrelated, already-unrestricted same-user host process. Initial executable/loader trust, ordinary launch size limits, and caller-supplied stdio authority remain normal OS launch responsibilities.

Job suspension/resumption and application restart are outside the runner contract. [Linux compatibility](LINUX_COMPATIBILITY.md) describes host requirements and procfs review.

## Executable acceptance tests

The public suites run the built executable with Rust and system-command fixtures; none require MCP Console. The [bootstrap contract suite](tests/bootstrap_contract.rs) includes the modules below.

| Required behavior                     | Coverage                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native entry and execution selection  | Native entry without a setup descriptor, inherited SIGPIPE, closure of helper-held stdin readers, direct init signals, and omitted/null/explicit bubblewrap selection in `native_entry`.                                                                                                                                                                    |
| Status, signals, and retirement       | Normal and nonzero completion, signal status mapping, inherited dispositions and masks, waitable children, and retirement of interrupted roots and detached descendants in `lifecycle`.                                                                                                                                                                     |
| Descendant observation                | Normal root exit after observed descendants detach in `startup`; unobserved owned-group children, held streams, and partial output in `retirement`. Darwin uses discovery checkpoints and verifies that an unrelated host process survives; Linux uses its PID namespace.                                                                                   |
| Startup cancellation                  | Cancellation before target release and while bootstrap input is incomplete in `startup`; SIGTERM and owner death at readiness, during partial setup, and with a stopped reader in `cancellation`.                                                                                                                                                           |
| Private storage                       | Successful and nonzero exits, replacement, mode-zero directories, and symlinks in `lifecycle`; removal failures in `startup`.                                                                                                                                                                                                                               |
| Discovery and termination failures    | Darwin syscall fault injection in `startup` checks diagnostics and retained private storage. Linux `prerequisite` covers seccomp restrictions, native-wait failures, and stopped-init deadlines.                                                                                                                                                            |
| Transport and accepted configuration  | Binary stdin independent of bootstrap, one immutable accepted frame, prompt stdin closure, regular-file offsets and shared descriptions, terminals, null/closed stdin, and bootstrap descriptor closure in `transport`; parser and environment contracts in `configuration`.                                                                                |
| Terminals and process groups          | Terminal interrupts, foreground peers, and parent-owned terminal input/output in `terminal`. Direct init signals cover both `setsid` and `setpgid`, with descriptor gates separating consumption from forwarding so duplicate standard signals cannot coalesce unnoticed.                                                                                   |
| Isolation and supervisor loss         | No launcher/proxy descriptors reach the target; `security` checks same-user control denial, fixed accepted policy, and native enforcement after supervisor loss. `startup` checks that target loader code runs only after enforcement.                                                                                                                      |
| Filesystem, network, and proxy policy | Denied/granted writes, independent direct networking, managed proxy allowlists, Seatbelt extensions, and native built-in profiles in the bootstrap and `policy` suites. Restricted networking checks socket-operation denials while retaining permitted descriptor I/O. `reference` executes documented payloads through production parsing and conversion. |

The `ownership` suite adds caller-only SIGKILL, caller-group SIGKILL with terminal stderr, Linux runner SIGKILL, and Linux pre-exec/readiness/partial/stopped startup checkpoints. Its independent observer pins exit notifications outside the killed group and kills observed leftovers on failure. Linux runs both an empty helper PATH for bundled selection and the ordinary host PATH, with and without the proxy. Shared-file-description and interruption contracts also exercise parent-owned launches.
