# Windows managed proxy validation, 2026-10-12

This is an implementation candidate, **not completed dedicated-account acceptance**. Do not enable Console's Windows proxy admission solely on the passing restricted-token or ordinary package tests. The final elevated refresh was canceled by Windows (1223), and no further provisioning attempts were made. The user's authorization had already been granted; the repeated prompts came from the original per-account implementation. Setup now batches the base identity and four slots under one elevation. That revised setup path has compiled but has not completed on this machine.

The ownership simplification reuses Codex's shared Windows ingress and configuration APIs, removes duplicate per-slot mutexes and the added native IPC field, and checks provisioned settings before using native `Preserve`. Both ports remain reserved when SOCKS is disabled; any allocator fallback is rejected before route registration or launch. The four account pairs, protected installation owner and durable quarantine remain. One already-authorized setup invocation during this revision also returned 1223 before the helper started. It was not retried and no further approval was requested.

## Acceptance present but not established on the final revision

The ignored tests use the public unversioned `--config-env` transport and separately spawned companions with the provisioned accounts. They cover:

- HTTP, CONNECT, SOCKS5 TCP, domain allow/deny precedence, limited GET versus POST/tunnels, authenticated TLS through CONNECT, and trusted HTTP/CONNECT upstream routing.
- Mixed-case hostile workload proxy values, independent policies and local-access classes, simultaneous proxyless restricted execution, other sessions' endpoints, forged restricting SIDs under both another sandbox account and the host account, and protected pool canaries even with an explicit write grant over the state directory.
- IPv4/IPv6 loopback TCP/UDP, actual UDP receipt, TCP listening and inbound UDP, with online and local-enabled positive controls; all reserved ingress-port bind attempts.
- Fixed-port conflicts, pool exhaustion, missing provisioning/capabilities, prelaunch failure, normal and nonzero exits, descendant retirement, owner-death cancellation, companion loss, native helper loss, blocked cleanup, quarantines and reuse of the exact retired slot.
- Concurrent admission by separate processes with SOCKS disabled, reservation of the disabled SOCKS port, and rejection of conflicts on either port with SOCKS enabled or disabled.

External IPv4/IPv6 TCP cases report unavailable positive controls. Non-loopback UDP requires `MCP_CONSOLE_SANDBOX_TEST_ECHO_ADDR`; run with controlled IPv4 and IPv6 peers separately. A WSL IPv4 echo server had a successful host UDP control, but the final sandbox probe was not run. Echo probes establish round-trip behavior only: a blocked reply does not prove that an outbound datagram never reached the peer. The suite reports external UDP egress as unestablished even when its echo assertions pass. Acceptance needs receiver-side observation at controlled IPv4 and IPv6 peers. Loopback UDP already checks actual receipt at the host listener. External IPv6 and final native UDP enforcement remain unestablished. An explicit Ctrl+C managed-proxy acceptance case and a transport variable whose name itself collides with a projected proxy variable are not covered by the new suite. Owner death covers the cancellation path, not delivery of the actual console signal. Setup failure/owner rejection paths, reserved IPv6 port binds and online-account port guards also lack dedicated acceptance cases. Linux/macOS runtime tests and a Windows Bazel build/test were not run.

## Review and delivery order

The full change, including added files, was reviewed against the branch baseline, with focused security, integration/context, test, and size reviews. Findings corrected:

| Finding                                                                                    | Correction                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cross-slot capability-store tampering could borrow an identity                             | Console mappings moved into `.sandbox-secrets/cap_sid`; every Console account receives the common secrets-deny group; slot write grants exclude the pool. A public canary regression was added. |
| Generic PTY adaptation converted missing native receipts to `-1`                           | Console preserves receipt absence across the adapter and suppresses native Exit on failed retirement.                                                                                           |
| A confirmed target exit 125 looked like retirement failure                                 | Receipt presence is retained separately from all 32-bit exit codes.                                                                                                                             |
| Prelaunch failures consumed durable slots                                                  | Lease drop rolls back before the native spawn boundary; post-spawn uncertainty remains quarantined.                                                                                             |
| Explicit setup could not repair stale account passwords                                    | Explicit setup refreshes even when account records exist.                                                                                                                                       |
| Slot recovery guidance referred only to plain setup                                        | Managed-session diagnostics now point to `setup --managed-proxy` against the original base state directory.                                                                                     |
| Status overstated pool readiness                                                           | `managed_proxy_provisioned` reports the completed marker and registered owner; it makes no free-capacity/account-health claim.                                                                  |
| Lifecycle tests could reuse a different slot or erase a quarantine without observing death | Tests derive the actual lease from the endpoint, assert exact-slot reuse, retain process handles, and serialize acceptance. Startup/reply/retirement waits are bounded.                         |
| External UDP echo absence was presented as outbound enforcement                            | The test now reports external UDP egress as unestablished; receiver-side observation remains required.                                                                                          |

The feature exceeds the usual 800-line change guidance. The smallest independently useful stage is preservation of native retirement receipts across adapters with its executable regressions. Subsequent stages are dormant native pool/provisioning and environment isolation; account-authenticated ingress; companion activation with network/lifecycle acceptance and documentation. Draft [PR #12](https://github.com/t-kalinowski/cobox/pull/12) retains the complete candidate for review. No merge, release, Console change or resolver change was performed. Final dedicated-account acceptance is required before rollout.

2. Run the serial acceptance recipe in [WINDOWS.md](WINDOWS.md#managed-proxy-ownership), including controlled external TCP/UDP peers and the untested signal case, before rollout.
3. In mcp-console, update the companion pin to the reviewed final cobox commit only after that acceptance succeeds. Enable Windows configuration admission for the supported capability set, retain rejection of UDP/Unix options, and retain the unversioned environment transport.
4. Surface setup-required, port-busy, pool-busy and quarantine diagnostics. Capacity is two strict and two local-enabled sessions; queue or report exhaustion without backend fallback. Treat failed cleanup as failed retirement, preserving replacement gating.
5. Keep resolver sandbox parity as a separate integration task. SOCKS uses the existing direct connector; trusted upstream selection applies to HTTP/CONNECT as on the existing runtime.

Recovery after unconfirmed retirement is deliberately manual and conservative; see [WINDOWS.md](WINDOWS.md#managed-proxy-ownership). A disappearing companion PID does not authorize deleting its lease or admitting a replacement.
